## 📋 PROJECT ARCHITECTURE OVERVIEW
===================================================================================

### Security Architecture:
```
Request → JwtAuthenticationFilter → SecurityFilterChain → Controller
              ↓
         Extract JWT → Validate → Load User → Set Authentication
```

### Package Structure (Package-by-Feature):
```
com.babyshop.api/
├── common/          # Shared components
│   ├── controller/  # Common endpoints
│   ├── dto/         # Common DTOs
│   ├── entity/      # Base entities
│   └── exception/   # Exception handling
├── config/          # Spring configurations
├── security/        # JWT & security components
├── user/            # User feature module
│   ├── entity/
│   ├── repository/
│   ├── service/
│   ├── controller/
│   └── dto/
└── [future modules: product/, order/, payment/, etc.]
```

### Database Design Principles:
- UUID for all primary keys (no internal IDs exposed)
- Soft delete on all main entities (is_deleted flag)
- Audit fields on all tables (created_at, updated_at, created_by, updated_by)
- Denormalized data in orders (historical record keeping)
- Price stored in paisa (1 BDT = 100 paisa) for precision
- Proper indexes for performance
- Foreign key constraints for data integrity

### Security Layers:
1. **Network**: CORS, HTTPS (production)
2. **Authentication**: JWT with refresh tokens
3. **Authorization**: Role-based access control
4. **Input Validation**: @Valid annotations + custom validators
5. **Data**: SQL injection prevention, password hashing
6. **Output**: No sensitive data in responses/logs
7. **Audit**: Complete audit trail
